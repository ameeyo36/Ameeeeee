# Figure → 可編輯 PowerPoint

## 跨平台執行

本技能以通用 Agent Skills 的 `SKILL.md` 為唯一必要入口，可由 Codex、Claude Code 或 Claude 的自訂技能功能載入。`agents/openai.yaml` 僅供 Codex 顯示與提示使用，執行不依賴它。依目前環境提供的檔案、圖片、簡報與渲染能力工作，不假定另一平台的工具名稱、固定路徑或套件存在。缺少必要能力時，明確說明受限步驟與已完成產物。

## 目標與輸入

使用者上傳 PNG、JPEG、WEBP 等 figure 後，分析圖像與遮擋，拆出文字、影像、icon 與幾何元素，輸出可於 PowerPoint 自行編輯的 `.pptx`。以原圖為視覺依據，不改寫文字、不美化、不重排、不替換風格。回覆預設使用繁體中文。

以 100% 原圖還原為目標，但不可承諾從扁平圖片恢復不存在的圖層資訊、被遮住的像素或未提供的字型。區分「視覺相似」與「物件可編輯」，未經驗證不得宣稱 100% 相同。若尚未提供 figure，請使用者上傳；不要把技能說明當成待重建的圖。

## 1. 檢視原圖與建立物件清單

以原始解析度檢視整圖，再放大細節。記錄寬高、比例、背景、主要區塊、對齊線與邊界。每张來源圖預設重建一張投影片。PPTX 全檔共用頁面大小；來源比例不同時，預設分別輸出，避免拉伸或裁掉內容。

為每個有意義的元素建立穩定 ID，類型至少區分 TEXT、IMAGE、ICON、SHAPE、LINE、ARROW、CHART、TABLE、BACKGROUND、EFFECT、UNKNOWN。記錄：

- 原圖像素 bbox `[x, y, width, height]`、旋轉、透明度、填色、外框與線寬。
- 前後順序、交疊對象、群組、判讀可信度與不確定原因。
- 文字逐字轉錄、換行、字型或替代字型、字重、字級、對齊、行距及上下標。
- 重建方式與實際編輯能力。

可信度若非 OCR 引擎回傳，標示為人工判斷；不能偽造精確機率。

## 2. 分析交疊與拆層

此步不可省略。辨識文字壓在圖片上、icon 與底圈、透明遮罩、箭頭穿越形狀、陰影與重疊卡片等關係，建立 back-to-front 順序。bbox 相交只是候選，需依可見輪廓判斷遮擋。

裁切範圍不等於乾淨圖層。當文字或 icon 將另行重建時，移除底圖中對應的烘焙內容，避免重影；保留邊缘抗鋸齒與透明度。簡單底色可重建為原生形狀；複雜圖片需遮罩或局部修補。涉及圖像編輯時，遵循環境的圖像編輯工具要求；不得假定任一像素處理工具必定可用。

被遮住的細節無法由單張圖證實。將修補標為推估，不編造科學、醫療或數據內容。若不能乾淨拆開，保留最小必要的複合圖片區域，記錄未拆解元素，不能刪除、偷偷改造或以重複文字掩蓋問題。

## 3. 選擇可編輯表示方式

| 元素 | 重建方式與限制 |
|---|---|
| 可辨識文字 | 原生 PowerPoint 文字框或表格儲存格；OCR 後逐字目視校對，保留大小寫、標點、符號、換行與上下標。 |
| 矩形、圓、面板、箭頭、連接線 | 優先原生形狀、線條或自由曲線，還原端點、線寬、虛線、箭頭與 z-order。 |
| icon、簡單向量 | 優先原生幾何；其次 SVG；最後透明 PNG，與文字及底板分離。 |
| 照片、紋理、複雜插畫 | 獨立圖片物件，保持裁切、比例、透明度與位置。圖片可移動、縮放、替換，不代表內部像素可逐一編輯。 |
| 圖表 | 有可靠原始數值時用原生圖表；僅能量測時標示數據為估算，不能冒充原值。客製科學圖可用形狀與線條，並說明沒有可編輯數據表。必要時保留圖形區圖片，分離標題、座標標籤與圖例。 |
| 表格 | 優先原生表格，恢復列欄、合併、邊框、底色與可編輯文字。 |
| 背景、陰影與效果 | 簡單者用原生填色與效果；複雜者只將必要區域保留為獨立圖片層。 |

SVG 可縮放、可選取，不保證能在所有 PowerPoint 版本直接修改內部路徑；只有實際轉成原生形狀並驗證後，才標示為原生可編輯。不得把整張來源圖當成重建結果，或覆蓋在物件上製造視覺相同的假象。

文字辨識不清或 AI 圖含偽文字時，不猜測其「原意」或自動修正。先完成可確定區域，再指出需要使用者補充的文字位置；保留原圖證據並標示未解決。缺字型時選已安裝且有必要字元的近似字型，依實際渲染調整字寬、大小與換行，記錄替代。

## 4. 產生 PPTX

使用可用的簡報製作技能與工具完成實際檔案；若環境提供簡報技能（例如 `presentations` 或 `pptx`），讀取並遵循其建置與渲染流程。沒有這類技能時，使用環境已提供的 PPTX 製作套件與渲染器。先檢查可用能力，不預設安裝有 Microsoft PowerPoint、OCR、SVG 轉換器或特定 Python 套件；不得因工具名稱不同便認定無法執行。

以來源比例設定投影片尺寸，按絕對座標放置物件：

`ppt_x = x / source_width * slide_width`，y、w、h 同理。

由後往前建立圖層，還原相對位置與群組。命名選取窗格物件，如 `TXT_Title`、`IMG_Photo_01`、`ICON_Heart`、`SHAPE_Card_01`。群組需能取消群組；群組不應破壞物件編輯能力。

## 5. 渲染、比較與修正

實際渲染產出的 PPTX，而非重繪另一張預覽假充結果。將渲染與原圖對齊至相同畫布，不使用局部變形掩蓋偏差。檢視並修正：

- 漏字、錯字、文字截斷、換行、字型、大小與文字重影。
- 元素位移、尺寸、比例、顏色、邊框、陰影與遮擋順序。
- 缺失圖層、未清除的底圖內容及物件被整張圖遮蓋。

產生半透明疊圖及絕對像素差異圖。需要量化時才計算 SSIM 等指標，記錄對齊方式、解析度、工具與實際分數；SSIM 不等於文字正確率或可編輯性，也不能轉稱「還原百分比」。重點檢視文字及重要區塊，避免大面積背景掩蓋局部錯誤。

檢查 PPTX 物件結構與文字內容，核對原生文字、形狀、圖片及圖表資料。若能使用 PowerPoint，另驗證代表性物件可選取並修改；只檢查 OOXML 時，明確區分結構檢查與實際應用程式驗證。修正重大差異後再渲染；若環境缺少渲染器，提供已生成檔案但明確標示尚未完成視覺驗證，不製造預覽或測試結果。

## 交付與驗收

交付可下載的 `reconstructed_editable.pptx`，以及實際產生的 `reconstructed_preview.png`、`comparison_overlay.png`、`difference_map.png`、`reconstruction_report.json`；多圖使用編號或分目錄。缺少的驗證產物須註明原因。

報告包含來源尺寸、投影片尺寸、各物件 bbox、z-order、遮擋關係、OCR 文字、可信度來源、重建方法、替代字型、推估修補及未解決差異。以 `native_text`、`native_geometry`、`native_chart_data`、`svg_image`、`raster_image`、`composite_raster` 明確標示編輯能力，不只用單一 editable 布林值。

最終以簡短繁中說明原生文字、形狀、SVG、圖片與未拆解元素數量，列出重要偏差及驗證狀態。驗收須有有效 PPTX、正確比例、無明顯漏項或重影，且可辨識可分離文字已原生重建。任何尚未達成的條件應列為未完成項，不宣稱完全還原。
